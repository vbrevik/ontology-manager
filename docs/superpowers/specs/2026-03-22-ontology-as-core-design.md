# Ontology as Core Application Feature

**Date:** 2026-03-22
**Status:** Draft
**Branch:** feat/ontology-sources

## Problem

The ontology browser is the primary tool users interact with, but it's buried under `/admin/ontology/browser` alongside governance and security settings. This makes it feel like an admin-only feature rather than the core of the application.

## Decision

Promote the ontology browser to a top-level route at `/ontology` and make it a primary navigation item. Keep schema governance (versions, designer, approvals) under `/admin`. The detail panel gains a tab system for future graph and relationship views.

## Design

### 1. Routing

**New route:** `frontend/src/routes/ontology.tsx` at `/ontology`
- Renders the existing `OntologyBrowser` component
- No sub-routes — tab switching is internal component state, not URL-driven

**Removed route:** `frontend/src/routes/admin/ontology/browser.tsx`
- Delete the file (or redirect to `/ontology`)

**Unchanged:** All other `/admin/ontology/*` routes remain (Classes, Relationships, Graph, Designer, Contexts, Versions). These are schema governance tools.

### 2. Navigation

**MainSidebar** (`frontend/src/components/layout/MainSidebar.tsx`):
- Add "Ontology" as the second item, after Dashboard
- Icon: `Network` or `GitBranch` from lucide-react
- Links to `/ontology`

```
Dashboard    (/)
Ontology     (/ontology)    <-- new
Projects     (/projects)
Targeting    (/targeting)
...rest unchanged
```

**Admin Approvals workspace sidebar** (`frontend/src/components/layout/WorkspaceSidebars.tsx`):
- Remove the browser link (it now lives at top level)
- Keep: Classes, Relationships, Graph, Designer, Contexts, Versions

### 3. Detail Panel Tabs

When a class is selected, the detail panel shows a tab bar:

| Tab | Content | Status |
|-----|---------|--------|
| Detail | ClassHeader + ClassProperties + ClassConflicts | Working (current implementation) |
| Graph | Placeholder: "Graph visualization coming soon" | Stub |
| Relationships | Placeholder: "Relationship explorer coming soon" | Stub |

When no class is selected, the placeholder "Select a class to view details" shows without tabs.

**Implementation:** A `useState`-based tab switcher wrapping the existing `ClassDetail` content. No routing, no URL changes. The tree panel is unaffected by tab selection.

### 4. File Changes

| File | Action |
|------|--------|
| `frontend/src/routes/ontology.tsx` | Create — new top-level route |
| `frontend/src/routes/admin/ontology/browser.tsx` | Delete |
| `frontend/src/components/layout/MainSidebar.tsx` | Modify — add Ontology nav item |
| `frontend/src/components/layout/WorkspaceSidebars.tsx` | Modify — remove browser link from Approvals workspace |
| `frontend/src/features/ontology/components/ClassDetail/ClassDetail.tsx` | Modify — add tab bar |
| `frontend/src/routeTree.gen.ts` | Auto-regenerated by TanStack Router |
| Integration test + Playwright spec | Update route paths |

### 5. Auth

The `/ontology` route uses the same auth middleware as the rest of the authenticated app. No permission changes needed — if a user can reach the dashboard, they can reach the ontology browser.

## Scope

**In scope:**
- New route, nav item, old route removal
- Tab bar in detail panel (Detail working, Graph + Relationships as stubs)
- Test updates for route changes

**Not in scope:**
- Graph visualization implementation (future cycle)
- Relationship explorer implementation (future cycle)
- Changes to admin governance routes
- Changes to dashboard, projects, targeting, or other sections
- Auth/permission model changes

## Follow-up

The Graph and Relationships tabs are stubs in this cycle. They will be implemented in a subsequent planning cycle once the core restructure is stable.

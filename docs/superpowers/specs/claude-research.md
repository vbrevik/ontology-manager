# Research: Ontology as Core

## Codebase Research

### Routing
- TanStack Router v1 with file-based routing. Files in `src/routes/` map to URLs.
- `routeTree.gen.ts` auto-generated by Vite plugin on file changes.
- Adding a new top-level route: create `src/routes/ontology.tsx`, export a `Route` with `createFileRoute('/ontology')`.

### Layouts
- `__root.tsx` wraps everything (providers, navbar, footer).
- `admin.tsx` is a layout route that detects workspace from `location.pathname` and renders the matching sidebar.
- `MainSidebar.tsx` has nav items with icon, label, href. Active detection via `pathname.startsWith(href)`.

### WorkspaceSidebars
- `ApprovalsWorkspaceSidebar` currently includes ontology governance items (Classes, Relationships, Graph, Designer, Contexts, Versions). Browser link is NOT in the sidebar — it's only accessible via direct URL.
- Each workspace sidebar uses `WorkspaceSidebar` component with `requiredPermission` filtering.

### Auth
- No explicit route guards. Auth checked in components and sidebar item visibility.
- `credentials: 'include'` needed on all API calls.
- CSRF token from cookie on unsafe methods.

### Testing
- Vitest + @testing-library/react for component tests.
- Playwright for E2E: auth via register+login API, token in localStorage, navigate to route.
- Ontology browser tests at `src/features/ontology/components/OntologyBrowser.integration.test.tsx` and `frontend/tests/ontology-browser.spec.ts`.

## Web Research

### TanStack Router File-Based Routing
- Flat notation (dots): `routes/ontology.tsx` → `/ontology`
- Directory notation: `routes/ontology/index.tsx` for routes with children
- Pathless layouts (`_name.tsx`): share UI chrome without adding URL segments
- Route tree regenerates automatically on save with Vite plugin
- **For our case:** Simple `ontology.tsx` at route root. No children needed since tabs are internal state.

### React Tab Patterns (Accessibility)
- WAI-ARIA pattern: `tablist` > `tab` + `tabpanel` with `aria-selected`, `aria-controls`, `aria-labelledby`
- Keyboard: Arrow keys navigate tabs, Tab enters/exits tablist
- **Shadcn Tabs component** already available in project (Radix-based): use `defaultValue` for uncontrolled state
- Keep tab state local (`useState` or `defaultValue`), don't lift to global store
- Automatic activation (default): tabs switch on focus. Manual: require Enter/Space. Use automatic for our case since tab content is local.
- Don't use tabs for > 6 items
- **Recommendation:** Use shadcn `Tabs` component with `defaultValue="detail"` for the detail panel. Three tabs: Detail, Graph, Relationships.
